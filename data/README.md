# Data dictionary

`hypotheses.csv` is the main prediction register for v0.4.0: one unverified candidate per row, with ordinal `rank`, explicit `prediction`, conditional nominal **total** capacity scenario, required assumptions, strongest ordinary alternative, cohort hypothesis, and conditions for raising/lowering the rank. `confidence` is a qualitative assessment, not a probability. All five rows have `hypothesis_status=unverified_prediction`; physical excess, healthy excess and software access are separately `not_established`. A low-confidence first place is possible. A30/PG199 have fragile relative ordering. Source IDs justify the stated inputs, not the hypothetical total capacity. No invented hardware observations are stored here.

In `devices.csv`, `priority` now contains `prediction_rank_1` through `prediction_rank_5` for the corresponding candidates, or `control` / `reference`. These are display labels copied from `hypotheses.csv`, not a result of the screening formula. The previous P1/P2 labels described information-collection priorities; v0.4.0 replaces them with the explicit prediction ranking. Larger conditional capacities remain in `hypotheses.csv`, never in factual capacity or width columns.

`devices.csv` has one row per named reference configuration, not per sample. Empty cells mean unknown/not established, never zero. `nominal_capacity_gb` preserves advertised GB-class labels for approximate comparison; for owner reports with GiB labels it is a nominal class, not a conversion into decimal GB. `runtime_total_mib` is filled only where a source explicitly uses MiB; the hashcat report uses MB and is described in notes instead. `effective_bus_bits` is filled only for a directly sourced width (manufacturer or attributed external report); `peak_bandwidth_gbps` means decimal GB/s (bytes, not bits) from a vendor or explicitly labeled external peak specification. The script accepts `bus_status=vendor`, `owner_verified` or `community_report` for computation, leaving missing or unverified widths blank. `reference_density_gb` is a chosen stated comparator, not automatically the minimum compatible density. `reference_basis` records its rationale. The output's q ratio is a heuristic, not a physical estimate. Source IDs refer to `docs/sources.md`.

`market_observations.csv` has one row per listing snapshot/transaction, never equating a sold counter with individual transactions. `observed_utc` may be a date if exact time is unavailable (note precision); `source_updated_at` is separate. Unknown quantities and shipping stay empty. Preserve original currency. `price_type` is `ask` or `transaction_verified` or `transaction_unverified`. No market index is computed from the single seed observation.

`supply_events.csv` records dated, sourced historical context. `date_type` distinguishes announcement, protocol event and fiscal period end. `inference_limit` specifies why each event is not proof of actual lot substitution. The table is not a supply quantity or HBM inventory time series.

`lot_observations.csv` is intentionally header-only until actual owner evidence is submitted. One row per anonymized device observation, with a stable sample ID reused for repeated observations; no full serial/UUID. `date_type` identifies the manufacturing stage or nonmanufacturing event, `date_start`/`date_end` are inclusive bounds (ISO dates where supported), and `date_precision` and `date_source` document provenance. Raw redacted codes are not presumed decodable. `cohort_id` is a sourced non-identifying group, not an inferred lot number. Unknowns stay blank. `hbm_density_bytes_per_stack` and `populated_stack_count` require physical evidence; never derive them just from bus width. `runtime_total_mib` is driver telemetry, `validated_distinct_bytes` is experimentally verified coverage, not total physical capacity. `evidence_status` can be `unreviewed`, `source_checked`, `replicated`, or `contradicted` for the stated claim; retain negative and uncertain records. `acquisition_channel_category` must not identify the owner. See [lot protocol](../docs/lot-history.md).

Keep source claims and predictions in their respective fields. Public-source corrections and alternative theoretical explanations can update the hypothesis register without hardware ownership. For actual runtime samples, use issues and supply redacted logs with provenance and explicit coverage.
