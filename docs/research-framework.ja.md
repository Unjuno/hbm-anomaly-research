# HBM追加容量研究の理論的枠組み

[日本語README](../README.ja.md) · [予想ランキング](ranking.ja.md) · [順位の考え方](ranking-method.md) · [物理モデル・導出（英語）](theory.md) · [ロットと経済モデル](lot-history.md) · [出典台帳](sources.md)

**v0.4.0 / 2026-11-25。予想ランキングを支える理論文書。新たな実機測定は行っていない。**

## 1. 研究目的と、区別する四つの主張

目的は、低容量として販売されたHBM搭載GPUについて、**何がどう怪しいかを理論から予想し、その理由を比較して順位を付けること**である。主成果は[予想ランキング](ranking.ja.md)にまとめた。本書は、予想が依存する物理モデル、製造条件、観測の限界を説明する。実機のない段階でも仮説を公開し、事実との境界、反対材料、予想が変わる条件を示す。

| 主張 | 確認したい内容 | 必要な証拠 | それだけでは分からないこと |
| --- | --- | --- | --- |
| 物理的な追加容量 | 公称データ容量を超えるデータ用DRAMセルが実装されている | 部品型番と密度の対応、実装の同定、対象基板との対応 | 正常性、アドレスへの公開、解除可能性 |
| 機能的な追加容量 | 公称データ容量を超える量を、このGPU上で独立して保持・読み書きできる | 正確な基準容量、同時常駐、アドレス依存パターン、別名参照の検査、エラーと試験範囲 | 長期信頼性、他個体での成功率、メーカーの意図 |
| ロットとの関連 | 追加容量や部品構成が特定の製造個体群に偏る | 根拠のある日付・部品・リビジョン別の比較、陰性例、入手元の独立性 | 供給不足が原因だったこと |
| 供給事情による代替 | 供給・在庫・納期の事情が部品や完成パッケージの転用を引き起こした | 該当部品・工程・時期に結び付く変更通知や説明など | 他SKUにも同じ判断が適用されたこと |

これらは別々に判定する。例えば、物理容量は確認できても正常にアクセスできない個体はあり得る。逆に、独立した追加メモリの動作を確認しても、製造時の意図や具体的な部品密度がすべて分かるとは限らない。

**用語の境界：** 本研究の物理容量はユーザーデータ用セルの容量とし、専用ECC用セルや予備セルを分ける。正常性とアドレス可能性も別の性質であり、不良セルがアドレス可能な場合がある。画面に表示された容量、BARの大きさ、空き容量、予約領域を除いた総量、試験で検証できた量を混同しない。MicronはHBM2Eのデータ用容量とECC用セルを区別しており、NVIDIAの管理ツールも予約領域等を区別する [S01,S31]。

## 2. 三層の説明モデル

| 層 | 主な問い | 得られる結論 |
| --- | --- | --- |
| 物理・アーキテクチャ | 容量、データ線数、転送速度、チャネル構成は整合するか | 既知の通常構成で説明できるか、追加確認が必要か |
| 製造・経済 | 同じ公称SKUに異なる部材や完成パッケージを使う条件は何か | 代替が合理的になり得る条件と、比較すべき個体群 |
| 観測・因果推論 | 観測がどの主張を識別できるか | 個体についての結果、再現の範囲、未解決の対立説明 |

価格と在庫の観測は調査対象を絞る補助情報になる。ただし、価格から物理容量へ直接結論を進めることはできない。各層で情報を追加して初めて説明が絞られる。

## 3. 帯域と容量の関係

### 3.1 変数表と前提

以下はHBM2/2Eのデータ用I/Oを対象にした理想ピーク帯域モデルである。実効バス幅が正しく分かり、全データ線が同じ実効ビットレートで動作する場合を扱う。専用ECC線は数えず、PCIe帯域やキャッシュ内の転送量とも区別する。

| 記号 | 意味・定義 | 単位（SIとの関係） | 定義域・前提 | 型 |
| --- | --- | --- | --- | --- |
| $w$ | 有効なデータ線の本数。仕様の「3072-bit bus」はここでは3072本と表す | 無次元の個数 | 正の整数。物理実装の全線数とは限らない | スカラー |
| $w_s$ | 比較の基準となるデータ線数。本書ではHBM2/2Eの1024本 | 無次元の個数 | 正の整数。本書の比較に固定 | スカラー |
| $r$ | 1本当たり実効データ転送速度。DDRクロックそのものではない | bit/s、秒はSI単位 | 正の実数。同じ動作条件で比較 | スカラー |
| $k_b$ | ビットからバイトへの換算係数、8 bit/byte | bit/byte、情報量の換算 | 固定値8 | スカラー |
| $B$ | データ用理想ピーク帯域 | byte/s | 正の実数。実測値ではない | スカラー |
| $C_0$ | 比較の基準にする公称データ容量を正確なバイト数に直した値 | byte、情報量単位 | 正の整数。GB/GiBの意味を確定できないときは未確定 | スカラー |
| $n_e$ | 有効データ線数を基準線数で割った値。実装スタック数ではない | 無次元 | 正の実数 | スカラー |
| $c_e$ | 基準線数当たりの公称データ容量 | byte | 正の実数 | スカラー |
| $d_{ref}$ | 出典と選択理由を明記した比較用のスタック容量 | byte | 正の実数。最小互換密度とは限らない | スカラー |
| $q$ | 基準線数当たり容量と比較用容量の比 | 無次元 | 正の実数。異常度の校正値や確率ではない | スカラー |

### 3.2 導出

1. 1本のデータ線が1秒に運ぶ量は転送速度に等しい。線数を掛けると全体のbit/sになる。
2. これをbit/byteの換算係数で割るとbyte/sになる。

$$B=\frac{wr}{k_b}.$$

3. 有効線数を1024本単位に換算する。

$$n_e=\frac{w}{w_s}.$$

4. 公称容量をその換算値で割る。上式を代入すると、同じ値を容量と線数から直接計算できる。

$$c_e=\frac{C_0}{n_e}=\frac{w_s C_0}{w}.$$

5. 出典付きの比較用容量がある場合に限り、相対比を求める。

$$q=\frac{c_e}{d_{ref}}.$$

**次元チェック：** 無次元の線数とbit/sの積をbit/byteで割るとbyte/sになる。容量を無次元の換算値で割った量はbyte、同じ単位の容量の比は無次元である。「bitとしての幅」に「bit/s」を掛ける説明では単位を二重に数えてしまうため、幅は線の本数として定義した。

**数値例：** 1024本、1本当たり3.2 Gbit/sなら、理想ピーク帯域は409.6 GB/s。GB/sのGは十進である。MicronのHBM2E資料では、8 GB級と16 GB級の双方が同じデータ線数と最大転送速度を持ち、4-highと8-highではチャネル数を維持してチャネル内容量を増やす [S01]。これは計算例と公表仕様の照合であり、ベンチマーク測定値ではない。

### 3.3 帯域から容量を一意に決められない理由

同じI/O幅・同じ転送速度の低密度部品と高密度部品を考える。帯域の式には記憶セルの密度が入っていないので、両者の理想ピーク帯域は一致する。実際に異なる容量の対応部品があるため、これは単なる未知変数の数え上げではなく、異なる容量が同じ帯域を与える反例である [S01]。

さらに、低密度部品を全領域公開する構成と、高密度部品のうち同じ容量だけを公開する仮想的な構成は、公称容量・有効線数・理想ピーク帯域の三つがすべて一致し得る。よって、その三つだけからどちらが実装されているかは判定できない。後者が実在するとの主張ではなく、観測だけでは排除できない説明を構成したものである。

したがって、**容量と帯域には普遍的な一対一のトレードオフはない**。有効チャネルを増減させれば両方が変わり得る一方、スタック内密度の変更では容量だけが変わり得る。実製品では電力・熱・信号・歩留まり・認定費用も制約になるが、それらの制約から一律の容量式は導けない。

### 3.4 スクリーニングの限界

既存ツールは公称「GB級」ラベルを使う概算比較であり、正確なバイト数での証明を実行していない。上記の式を厳密に適用する際は容量の単位を統一する。比較用密度は実在部材と互換性の根拠を示し、世代名から自動的に決めない。

ツールの強い相対不整合の境界は、相対比が0.5以下という便宜的な基準である。成功確率への変換、統計的な有意性、未発見製品への予測性能は検証していない。CMP 170HXは結果を知った上で選んだ対照例であり、この基準の独立評価には使えない。通常範囲の値でも非公開領域がないことは証明できず、不明なバス幅を仮定で埋めて順位を上げることもしない。

## 4. 製造ロットと供給制約

### 4.1 「余っている上位部品を入れる」は条件付きで合理的

**事実：** NVIDIAのFY2022開示には調達の前倒し、長い製造リードタイム、需要と在庫のずれのリスクが記載されている。ただし、特定HBMの不足・余剰や特定ロットの代替実装を記録した資料ではない [S22]。

**推論：** 同じ注文を満たす二つの認定済み構成を比べ、売上条件が同じなら、追加認定・転用・試験・故障リスク・機会費用を含む代替費用が、通常部材の調達費用と納期遅延損失より小さい場合、上位部品の転用は経済的に説明できる。計算と変数表は[経済モデル](lot-history.md)に示す。

**未検証の仮説：** その条件が特定SKUの特定期間に成立し、公称容量を維持したまま高密度HBMや上位パッケージが使われた。これを検証するには、会社全体の供給報告から一段進んだ、部品・工程・時期の証拠が必要である。

「在庫だから無料」ではない。高価格SKUに使える部品には機会費用がある。また、HBM単体の変更はパッケージ工程の問題であり、完成済みGPU+HBMパッケージを別製品に回すこととは異なる。インターポーザの配線、コントローラ対応、電源、冷却、試験、認定が合わなければ代替できない [S01]。

### 4.2 なぜ他製品でも同じことをしたとは言えないか

共通するのは「条件がそろえば転用が選択肢になる」という機構である。条件そのものは製品・時期で異なる。上位SKUの需要が強い、互換性がない、通常部材が安定供給される、追加領域が不良、といった事情で判断は変わる。

したがって、既知例があることは同世代・隣接世代を調べる理由になるが、全製品で同じ実装を予言する理由にはならない。逆に、ある1台が陰性でも、別の部品・製造期間の個体群まで否定できない。研究では両方の飛躍を避ける。

### 4.3 反証できる範囲を先に固定する

「どこかのロットにあるかもしれない」を際限なく維持すると、検証が終わらない。対象のSKU、基板番号、リビジョン、製造工程の日付範囲、比較群、追加容量の基準、試験環境を観測前に決める。日付が読めない場合は部品・リビジョンで分け、時系列の結論を保留する。

探索の出発点は、根拠を示して定めた初期・移行期・後期の3群で、各群2所有者、合計6個体である。これはばらつきを見つけるための目標であり、成功率の推定に十分な標本数ではない。同じ販売元・同じドナー在庫に由来する個体は相関し得る。所有者が2人いるだけでは製造由来まで独立とは言えない。

部材製造日、パッケージ組立日、PCB製造日、最終組立日、VBIOSビルド日、販売日を分ける。供給イベントの公表日を、そのまま個体の製造日や切替日として使わない。

## 5. 価格変動が追加できる情報

| 観測 | 調べる価値がある理由 | 代替説明・追加で必要な情報 |
| --- | --- | --- |
| 同じSKUの特定リビジョンだけ価格差が広がる | 個体属性を選別する需要の可能性 | 冷却・保証・付属品・状態・出品者の違いをそろえる |
| 公開された容量関連情報の前後で価格が変わる | 情報と需要の時間関係を検討できる | AI需要、アダプタ普及、演算性能の改善、為替も比較する |
| 出品が急に消える | 流通量の変化を調べる入口になる | 売却、出品撤回、再出品、アカウント停止を区別する |
| 同じ型番で値段が大きく違う | 部品・来歴の違いを調べられる | asking priceと成約価格、単体とセットを混ぜない |

同時期の近縁製品や別リビジョンを対照にし、出品の重複、送料、通貨、状態、件数を記録する。価格差が残っても、それだけで「誰かが隠れた容量を知って買っている」と結論しない。価格と物理実装を結び付ける追加証拠が必要である。

**現状の限界：** 台帳の価格情報は時系列分析に不足しており、本リリースは価格上昇率、トレンド転換、在庫減少を認定していない。詳細は[市場観測手順](market.md)を参照。

| 対象 | 現時点での役割 | 最も価値のある次の観測 |
| --- | --- | --- |
| CMP 170HX / CMP 100-100 | 外部の追加容量報告を持つ対照例 | 同一個体に対応する基準容量、検証範囲、部品・リビジョン差 [S03,S04a,S16] |
| CMP 100-200 | 仕様の不足を解消する候補 | 約6 GB級という外部ログに対応する有効バス幅と実装部品の確認。12 GBは条件付き [S02,S05] |
| A30 | ロット・物理構成を比較する候補 | 公称24 GB・3072本・933 GB/sは通常構成と整合。仕様上の容量不整合とは扱わず、部品・無効領域を独立確認 [S06] |
| PG199 / DRIVE A100 | OEM向け構成差を調べる候補 | 部品の密度と実装、修理来歴、32 GB級報告の対象個体 [S11,S12] |
| CMP 100-210 / A30X | 低優先の比較対象 | 性能改善と容量拡張を分け、異なる基板系統と陰性報告を照合 [S04,S10,S11,S14] |

## 7. 補助資料：予想を実機で確かめる場合

以下は所有者が実験する場合の整理であり、机上予想を掲載する前提ではない。予想は、支持材料・反対材料とともに先に公開する。

| 項目 | 本研究での定義 |
| --- | --- |
| H：反証可能仮説 | 事前に指定した個体または有限の個体群で、確定した公称データ容量を超える独立データを、指定した実機環境と試験時間に保持・読み戻せる。物理実装・ロット差・供給理由は別仮説とする。 |
| T：最小検証 | 標準状態の識別情報を収集し、既存の独立実験から正確な容量、同時常駐、アドレス別パターン、既存領域の再読出し、異常ログ、再起動後の結果を確認する。同一条件で別所有者の再現を求める。打切り条件と未完了扱いを先に記す。 |
| D：合否 | PASSは、明記した試験条件・範囲で、公称容量に事前指定の追加容量しきい値を足した量以上の独立データが検証でき、証拠・エラー・繰返し条件も満たした場合。明示した追加領域が再現して誤る場合は、その条件での機能仮説をFAILとする。容量表示だけ、初期化失敗だけ、基準容量不明、試験範囲不足はUNCERTAIN。物理容量不足は物理仮説の判定として別記する。 |
| C：破れ方 | 低密度部品、無効・不良チャネル、別名アドレス、ホストへの退避、MIG/vGPU制限、予約領域の解放、修理・換装、通常のOEM構成差。 |
| U：不確かさ | 部品型番の解釈、GB/GiB、日付の意味、未試験領域、エラー検出の限界、温度・クロック・電源、選択バイアス、共通入手元。誤差モデルと測定値がないので合成標準不確かさや包含係数は数値化しない。 |

基準は「空き容量」や「ドライバの予約を除いた総量」ではなく、単位が確定した公称データ容量である。以前使えなかった予約領域を使えただけでは、公称を超えるDRAMの証明にはならない。複数GPU・複数パスで再利用した同じ領域を足し合わせても追加容量にはならない。

CUDAのmanaged/unified memoryは環境によってホストへの退避やオーバーサブスクリプションを許すため、確保できた仮想メモリ量だけを数えない [S30]。有限回の試験は、その条件とパターンでの結果を支える。全アドレス・全温度・全寿命にわたる無故障の数学的証明ではない。

詳細な事前登録、しきい値の選び方、逐次停止、判定表は[検証計画](study-design.md)、ログ項目は[検証手順](validation.md)に分けた。実機がない段階でも、出典確認、欠損値の明示、比較群の設計、第三者が必要な観測を提出できる形の整備までは進められる。

## ERROR CHECK

- データ線数をbitという情報量と混同していない。帯域は理論値と実測値を分けた。
- 正常領域とアドレス可能領域を単純な大小関係に置いていない。
- ECC用セル・BAR・予約領域・ホスト退避を追加HBMと数えていない。
- 1024本単位の換算値を物理スタック数に読み替えていない。
- 出典付きの通常構成で説明できる製品を、仕様だけで異常と断定していない。
- 供給制約、ロット関連、追加容量、メーカーの判断をそれぞれ別の主張としている。
