# 世代と製造群をまたぐ再発を予想する

> **v0.10訂正:** この文書は歴史から仮説を作る背景資料です。類似性による旧順位は撤回しました。通常構成と余剰構成を区別する対象固有の情報は[現行評価](current-ranking.ja.md)と[推論の方法](diagnostic-inference.ja.md)で扱います。

[English](recurrence-hypotheses.md) · [現在のランキング](current-ranking.ja.md) · [先例台帳](../data/capacity_precedents.csv) · [製造原因](manufacturing-causality.ja.md) · [容量制約](capacity-constraints.ja.md) · [出典](sources.md)

**v0.9.0 — 2026-11-26 JST。公開資料からの予想であり、新しい実機測定はない。**

本研究は、過去に観測・報告された容量制限や過剰実装が、どの製品・製造群で繰り返された可能性があるかを予想する。歴史的な先例を、**候補を選ぶ積極的な根拠**として使う。関連世代に共通する商品化・製造上の機序を探し、それが現れそうな部品・製造群を具体化する。

中心となる問いは、**似た結果が以前にも生じたなら、現在のどの製品・製造群が、その結果を再び生む条件を共有しているか**である。対象の実部品が未同定でも、予想には価値がある。予想を支える事情、どこに集まりそうか、何が予想を弱めるかを記録する。実装確認と動作の健全性は、別の記録として維持する。

## 1. 先例から何を予想するか

結果が繰り返されていれば、低容量品を毎回無関係な出来事として扱うより、共通機序を調べる理由が強まる。共通アセンブリを複数の商品階級へ割り当てる、用途に応じて公開容量を制限する、利用可能な適合部品へ置き換える、完成パッケージの一部を除外して製品化する、といった判断が再利用される可能性がある。

先例が支える範囲は異なる。物理的な追加メモリの報告は、その結果が生じ得ることを示すが、メーカーの動機までは特定しない。容量を変更できた報告は、その構成経路の参照になるが、後の世代で同じ制御が使われるとは限らない。世代をまたいで予想する対象は、**製造・商品化の判断**であり、部品の適合性や設定方法は製品ごとに検討する。

### 世代・製造・観測・公開の日付を分ける

チップの世代、個別基板の製造日、観測・試行日、報告の公開日は別である。所有者が記録した試行日を、そのまま公開日にはしない。古いアーキテクチャについて、何年も後に新しい報告が出る場合がある。その報告は旧世代にも同種の結果があるという比較に使えるが、発見が別の報告より先だったとは示さない。

| 先例 | 確認できる歴史的な入力 | 予想への使い方 |
| --- | --- | --- |
| **RX 480 4 GB／8 GB、2016年** | AMDは両容量を発表。2016年7月の当事者による市販品報告は、4 GB表示のカードに8 GBのGDDR5実装を同定し、容量を拡張した動作を報告した [S53,S54]。調達事情の説明は同時代の報道であり、社内の調達記録ではない [S55]。 | 消費者向け製品でも、公称より大きな元の実装が共存し得る先例。一時的な調達上の代替は報告された説明として扱い、HBMの実装経路は別途検討する。 |
| **P104、2018-12-02の所有者投稿と2019年の議論** | ASUSのフォーラムに掲載された利用者投稿は、8 GB実装の半分が公開されていると主張する [S84]。後の所有者議論には混在した結果がある [S17]。ASUS上の投稿は利用者の主張であり、メーカーの保証や完全な容量検証ではない。 | 採掘用途の制限を旧世代へさかのぼって調べる先例。結果の混在は、全品一律よりも派生品・製造群ごとの予想を促す。別メーカーであるGigabyteの4 GB仕様 [S85]を、ASUS個体の実装証拠には使わない。 |
| **CMP 100-100、GP100系列** | GP100は2016年に発表されたアーキテクチャ系列 [S86]。所有者が2個体の容量変更の試行日として記録しているのは2026-11-02 [S04a]。CMP基板の製造日でも、確定した初回公開日でもない。 | Pascal系列のCMP報告は、VoltaのCMP派生品を調べる近い製品系列の先例になる。アーキテクチャの年代と報告の年代を分けて保持する。 |
| **CMP 170HX、GA100系列** | 外部研究は特定の8 GB・10 GB派生品について容量変化と派生品間の差を報告する [S03,S19]。本研究は最初の発見日を確定していない。 | 同じ採掘向け製品系列の後続アーキテクチャにも容量制限の参照例がある。関連CMPを調べる動機が強まるが、各派生品の部品と除外領域はそれぞれ説明する。 |

## 2. 三つの再発機序は、異なるロット差を予想する

以下は**作業上の原因仮説**であり、上の先例すべてについて確認された製造動機ではない。

| 再発機序 | 繰り返され得る理由 | 製造群についての積極的な予想 | 予想を弱める情報 |
| --- | --- | --- | --- |
| **継続的な商品区分としての容量制限** | 共通のアセンブリを用途・契約・価格帯ごとに割り当て、公開資源を変えられる | 似た部品・パッケージ群に、複数の改版・出荷を通じて持続する低容量設定が現れる。短期の不足ロットに限らない | 名指しした範囲全体で専用の低密度実装が使われる資料、または容量差が表示・集計だけである説明 |
| **一時的な適合部品の代替** | 通常のアセンブリが遅延したり不利になったりしたとき、利用可能な互換高密度品で納品できる | 同じ公称容量の製品内に、元の部品・改版が異なる高密度群が現れる。関係する組立・調達期間と結び付くが、在庫・出荷の遅れで期間がぼやけ得る | 代替品が未入手・非互換・他向けに確保済み・他用途でより有利、または対象部品が通常構成を継続して説明する |
| **パッケージ組立後の選別利用** | 完成パッケージの一部を無効化し、満たせる等級や必要な資源に合わせて下位製品へ使える | 同じパッケージ系列に物理資源を残したまま、有効領域や製品等級が異なる群が現れる。販売日だけより、パッケージ・設定・選別履歴でまとめる方が有効 | 該当の選別が余分なメモリを付ける前に終わっている、または対象製品が物理的に小さい専用実装を使う |

### 完成パッケージの再割当ては、代替の別の枝である

一時的な不足には、組立前に個別部品を変える経路と、完成済みの互換パッケージを再割当てする経路がある。後者が予想するのは、**パッケージの同一性を維持したまま、後に割当てや許された設定が変わること**である。HBMの日付コードが後になることや、新しくメモリ部品を製造することまでは予想しない。

不足しているのがパッケージ工程なら、この枝が重要になる。完成済みパッケージは不足工程を再び通さずに済む場合があるが、未実装の高密度HBMには組立経路が必要である。TSMCが2023年に前工程の対応力とCoWoSの制約を区別した説明は、不足の所在を見る意味を示す [S83]。供給上の出来事は、それが変えたと予想する個別の判断より前である必要がある。[製造原因の整理](manufacturing-causality.ja.md)参照。

### 選別理由によって、追加利用への見通しも変わる

演算部・電力・周波数の条件が降格理由なら、残されたHBMは健全な追加資源を探す対象になり得る。メモリや接続経路が降格理由なら、物理余剰に不良領域が含まれる可能性がある。これは予想の別の枝である。下位製品という名称だけでは決まらず、対応する試験・選別情報が評価を変える。

「初期ほど有利」「後期ほど有利」という一律の方向は置かない。継続的な商品区分、一時的な代替、後の在庫再割当ては、異なる時間的なパターンを予想する。関連する歴史的な機序から方向を選ぶ。

## 4. 通常構成にも、その成立を支える情報を求める

算術モデルは引き続き有用である。低密度の通常構成が、ある容量と幅を説明する場合がある。その物理的な成立可能性は、別の入力である。代替説明が必要とする部品も、信号速度・電圧・パッケージ・アドレス対応・時期の条件を満たす必要がある。

| 通常説明を支える情報 | 予想での扱い |
| --- | --- |
| 対象個体、または適用可能な対象製品構成の部品・実装資料 | 具体的な通常構成。その範囲について強い反対材料になる |
| 同系列の正規構成の資料 | 設計上近い、意味のある対立仮説。対象群へ適用できるかは別途考える |
| 部品カタログに密度が載るだけ | 部品は実在する。対象の認定、パッケージ適合、利用可能時期は別に裏付ける |
| 容量と幅の算術だけが合う | 必要な実部品と実装をまだ特定していない、可能なモデル |
| 主要な入力が未整理 | 欠けた情報を指定する段階。余剰構成・通常構成のどちらが不可能だという証拠でもない |

算術だけの通常可能性を、工場由来の部品同定と同じ強さの反論として扱わない。一方、不完全な公開カタログで低密度品が見つからないだけで、その部品が存在しなかったとはしない。**どの具体的な通常アセンブリが存在すれば異常を説明できるか**を明示し、それを探すことで予想を進める。

## 5. 実機確認の前でも、予想順位は更新できる

現行ランキングは、**歴史から動機付けられた再発予想**を比較する。部品系列、繰り返された商品化判断、製造期間、通常説明の強さに関する資料によって、順序を変えられる。別の `physical_status` 欄はそのまま未確認でもよい。

| 予想層 | 対象 | この位置に置く理由 |
| --- | --- | --- |
| **R1** | CMP 100-200 | 特に小さい報告容量、12 GBのVolta比較例 [S32]、Pascal系列とGA100のCMP参照例に挟まれた近い製品系列という手掛かり。幅の欠測で実測された帯域異常とは呼べず、比較例も対象の部品を特定しない |
| **R2、同順位** | A30、PG199、A800 40 GB Active、CMP 100-210、MI50 16 GB、H100 SXM5 64 GB HBM2e | 具体的なパッケージ系列、採掘製品での反復、密度移行、同世代構成の仮説を持ち、意味のある通常説明も残る |
| **R3、同順位** | H100 SXM5 80 GB、RX Vega 56／64、BC-160、A30X | 転用の類推が遠い、通常説明が強い、または対象固有のパッケージ関係が不足している |

以前のv0.8の具体性順位は、台帳の `v08_specificity_tier` に保存する。今回の変更は、予想に使う観点を明示したもの。同順位は同じ機序を意味せず、新たに測定した成功率でもない。

順位を更新する情報には、より近い先例、元の部品対応、通常構成の訂正、対象に適用できる製造上の出来事、提案した群を崩す反証がある。同じ話が複数サイトに載っても独立した再発事例は増えない。同じ仕様から計算した容量・幅の比率も、別の独立観測にはならない。

## 6. 机上の予想に使う簡潔な H／T／D／C／U

| 項目 | 適用 |
| --- | --- |
| **H — 予想** | 候補、繰り返されたと考える判断、予想する部品・製造群のパターン、対象の日付・歴史的な期間を記す。群の境界が不明であることと、有利なロットを発見したことを分ける |
| **T — 次の最小作業** | 提案した群と通常説明を最もよく区別する、一つの資料・部品関係を探す。一つの原資料で狭い前提が解決する場合がある。普遍的な十分資料数や購入条件は置かない |
| **D — 更新条件** | 関連する共通機序・対象の関係が裏付けられれば予想を強め、必要な関係が崩れれば弱める。PASS／FAILは名指しした前提に適用できる。対立説明が残れば予想はUNCERTAINだが、比較上の優先度は公開できる |
| **C — 対立説明** | 専用の低密度品、余剰を生まない計画的な部品共通化、不良メモリ、通常の再販、修理済みアセンブリ、表示・集計上の差 |
| **U — 不確かさ** | 出典の依存、不完全な部品カタログ、設定日の欠測、群境界の曖昧さ、修理来歴を記録する。適用できるモデルがない段階で、数値的な合成不確かさや確率を置かない |

製造群の定義を裏付けられる段階で固定する。その群に否定的な情報が出たら、否定結果を保持する。新しい群には新しい出所付きの理由が必要であり、反証のたびに名前のない別ロットへ逃がさない。一つの通常個体はその群の予想を狭めるが、広い再発仮説を全て消すわけではない。一つの肯定個体も、その構成を示すが市場比率までは示さない。

## 7. 関連分野と ERROR CHECK

**計算機アーキテクチャ**は容量・幅・アドレスの制約を与える。**パッケージ・信頼性工学**は元の部品実装、組立後の選別、修理を分ける。**産業経済学・製造史**は共通部品、代替、再割当てが合理的になる条件を考える。**因果推論**はアーキテクチャの年代、製造判断、後の報告、共有された証拠を分ける。これらを組み合わせれば、実機を所有していなくても予想を中心とする研究を進められる。

**次に考える問い：** 最上位候補について、どの元のパッケージ・部品関係が分かれば、広い製品系列の先例を特定製造群の予想へ変えられるか。

### ERROR CHECK

- 歴史的な先例を積極的な予想の入力とし、実機による直接確認を参加条件にしていない。
- アーキテクチャの年代、製造日、観測・試行日、公開日を分けた。
