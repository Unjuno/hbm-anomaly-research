# 現行版：余剰HBM仮説の統合ランキング

[English](current-ranking.md) · [トップ](../README.ja.md) · [容量・幅の制約](capacity-constraints.ja.md) · [製造原因](manufacturing-causality.ja.md) · [出典](sources.md) · [CSV](../data/current_ranking.csv)

**v0.8.0 — 2026-11-26。公開資料による考察であり、独自の実機測定はありません。**

## 1. 何の順位か

対象は「公称容量より多い通常データ用HBMが、その低容量製品の一部個体に実装されているか」という予想です。その先にある「余剰が健全か」「使えるか」は別の問いです。以下の新規予想では、いずれも直接の裏付けがありません。

**順位1〜3は、物理余剰を疑う根拠の具体性を比較した、同順位を含む候補層です。** 確率、流通量、購入価値、解除の成功率ではありません。同じ層の中を細かく並べる根拠は不足しています。第1層でも弱い予想です。「健全な追加容量」の直接証拠を基準にするなら、現状の新規候補に成功期待順を付けられません。

容量に直接関係する手掛かりや特定可能な同系列品の比較を、一般的な不足・余剰の話より重視します。通常構成で説明できる程度、資料の質、未確認の互換性・転用仮定も考慮します。点数の合算はせず、以下の判断理由を公開します。

**v0.8で順位層を動かさない理由：** 新しく導いたのは、既存仕様と明記した部品仮説が両立するための必要条件です。候補の実部品や新しい製造群を同定したわけではありません。以下の「機序の絞り込み」とCSVの `mechanism_constraint` を追加し、主張の具体性を上げました。数学的に条件を絞れたことを、発見の確率が上がったこととは扱いません。

| 証拠を要する問い | 新規予想11件に共通する現状 |
| --- | --- |
| 対象の低容量品に余分な通常データ用HBMが実装されているか | 未確認 |
| 余剰領域が明示した条件下で健全か | 未確認 |
| 余剰領域にアクセスでき、安定して使えるか | 未確認 |
| 当たり製造群や、その市場比率が分かったか | 未確認 |
| 検証済みの価格推移を順位へ反映したか | 反映なし |

GB級の構成例は**条件付きの総容量**です。実測値、使える容量、期待値、上限ではありません。出典が裏付けるのは観察・仕様であり、こちらの予想までメーカーが述べているわけではありません。

### v0.8で機序を絞った点

次は[チャネル分割モデル](capacity-constraints.ja.md)における条件付き推論です。容量を同じ単位にそろえ、通常データ容量・予約分を区別し、チャネル当たりの容量配分を仮定します。密度は候補個体で確認済みの値ではありません。

| 候補 | 今回狭めた説明 | 次に価値の高い資料 |
| --- | --- | --- |
| A30 [S06] | 同一密度8 GB級なら、有効な幅で24 GBを全て公開できるため、このモデルの余剰は無効領域側に必要。16 GB級なら有効領域内の一部公開が必要。通常のnative ECCだけで32 GBを24 GBにしたという説明は公式記述と合わない。 | スタック数だけでなく部品密度も分かるパッケージ対応資料。 |
| MI50 16 GB [S38,S80] | 4096本と同一密度8 GB級を置くと、スタック全体の停止だけで16 GBにする説明は成立しない。有効領域内で容量を減らす条件が必要。4 GB級なら普通に説明できる。 | 工場出荷由来の16 GB構成の部品密度。32 GB製品が存在するという情報の追加だけでは進まない。 |
| A800 40 GB Active [S71] | 5120本では8 GB級が全容量公開のモデル。16 GB級の仮説は有効領域内の部分公開と互換性を別途必要とする。 | 正確なパッケージ型番と、密度・互換性の資料。 |

複数の資料が同じ仕様を再掲していても、別個体の実装情報が増えたことにはなりません。容量・幅・その比率も、同じ入力から得た派生量を独立した三つの証拠として数えません。

### この順位にした理由と、逆転する条件

**第1層：** H100 64 GBには、同じHBM世代の64／94 GB構成を示す公式資料があります。CMP 100-200には低容量の個体表示と、別CMP製品の容量制限に関する先例があります。異なる種類の手掛かりなので両者を同順位とし、片方の成功率が高いとは主張しません。

**第2層：** A30、PG199、MI50、A800 Active、H100 80 GBは、実装数または密度を問う構成仮説を立てられます。一方、通常構成が公称仕様に合うため、細かい順序は付けません。MI50の16／32 GBという正規構成は比較対象であって、異常そのものではありません。後発のA800というだけでも転用は確定しません。

**第3層：** RX Vega、CMP 100-210、BC-160、A30Xは、部品移管・互換性などの仮定がさらに必要か、手掛かりに直接的な通常説明があります。Vegaの異なる搭載パッケージ、容量を変えないCMPの性能改善、A30Xの幅不明を反対材料として扱います。採掘用という属性だけでBC-160を上位にはしません。

順位は重視する証拠に依存します。実装の直接証拠を必須とすれば、**11件とも未確認**です。製品系列からの類推を採用しなければ、第1層を優先する理由も大幅に弱まります。部品の対応表が得られれば順位は逆転し得ますが、仮定上の容量が大きいというだけでは上がりません。

## 6. 今回の順位変更

v0.4〜v0.6で異なっていた順位の意味を、この表へ統合しました。旧資料・CSVは履歴と明示して残します。

- Intelを「調査優先度1位」から、公式に無効化を確認できる参照例へ変更。
- H20を「新規手掛かり2位」から、物理的な転用先が分かるまで供給監視へ変更。
- Blackwellの容量表記差を監視枠へ変更。同じ比率の差だけで共通の解除可能領域を推定しない。
- 根拠が僅差だったA30／PG199の細かい順位を廃止。MI50・A800・H100 80 GBも同じ弱い候補層で比較。
- 旧英語表・CSVのIntel第4基を無条件に16 GBと読める表現を修正。
- 新しい実機成功、確率、価格による加点は追加していない。
