# HBM Anomaly Research — 隠れたGPUメモリの公開検証

[English README](README.md) | [理論的枠組み（日本語）](docs/research-framework.ja.md) | [物理モデル・導出](docs/theory.md) | [検証計画](docs/study-design.md) | [候補台帳](docs/candidates.md) | [出典](docs/sources.md)

**2026年11月25日・v0.3.0：理論と検証計画を整理した公開研究。自前の実機検証は未実施。**

## 目的

HBM搭載GPUの公称容量、メモリバス幅、帯域、製造系譜、市場の観測を照合し、正常な未公開メモリ領域が残る可能性のある個体群を特定する。中古GPUを既に所有する人の協力によって、購入や危険な改造を前提とせず、反証可能な検証を進める。

CMP 170HXの一部で8→64 GB級、10→40 GB級、CMP 100-100で6→12 GiBという外部報告が存在する [S03,S04a,S16]。ただし、製品の全個体や全領域について保証された結果ではない。同じダイや外観だけでは、追加メモリの存在は証明できない。

## 理論の構造

| 主張 | 検証するもの | 別の証拠が必要なもの |
| --- | --- | --- |
| 物理的な追加容量 | 実装部品の型番・密度・構成 | 正常性とアクセス可能性 |
| 機能的な追加容量 | 公称容量を超える、独立かつ同時常駐したデータの読み書き | 長期信頼性と他個体の成功率 |
| ロットとの関連 | 製造時期・部品・リビジョン別の差 | 供給不足が原因だったこと |
| 供給事情による代替 | 該当部品・工程・時期に結び付く変更と理由 | 他製品での同じ判断 |

この四つを独立に判定する。価格変動は調査対象を選ぶ手掛かりとし、物理容量やメーカーの意図の証明には用いない。詳しい説明と反例は[日本語の理論的枠組み](docs/research-framework.ja.md)、合否と逐次停止は[検証計画](docs/study-design.md)にまとめた。

## 製造時期・ロット別の供給制約仮説

同じ型番でも、通常の部材が不足し、互換性のある上位パッケージが余っている時期には、従来仕様を維持して上位部品を転用する可能性がある。2022年度NVIDIAの10-Kでは、従来約6か月前だった調達を少なくとも12か月前に行うようになり、設計確定前の発注や余剰在庫のリスクも説明されている。ただし特定HBMの不足・余剰や転用は未確認。HBMはインターポーザ上に実装されるため、完成パッケージの再配分とHBM単体の変更を区別する。互換性、品質保証、上位製品への転用機会費用が制約になる。

製造時期を初期・移行期・後期に分け、同一SKU内の部品番号・密度・パッケージを比較する。発売日、VBIOS作成日、PCB製造日、パッケージ組立日、最終製品製造日、販売日は別の情報である。公開資料の時系列と実機のロット情報は別台帳とし、時間的相関だけから供給不足が原因と断定しない。詳しくは[製造ロット・経済モデル](docs/lot-history.md)、[歴史イベント台帳](data/supply_events.csv)、[個体観測台帳](data/lot_observations.csv)参照。

## 理論

HBM2/2Eでは、スタック当たりのI/O幅が同じでも、DRAMダイ密度や積層数が異なることがある。よって、容量当たり帯域が異常に大きいGPUは候補になり得るが、通常の低密度部品でも説明できる場合がある。無効チャネル、ダミー、不良選別、部材変更、ECC・予約領域、仮想化やMIGも対立説明である。

公称容量と有効データ線数が信頼できる場合、1,024本相当当たりの公称容量を、出典付きの比較用部材と照合する。実装スタック数はこの換算だけでは分からない。帯域が等しいことは物理密度の等しさを意味しない [S01]。記号・単位・導出は[日本語の導出](docs/research-framework.ja.md)、厳密な範囲と反例は[物理モデル](docs/theory.md)参照。

| 優先対象 | 現在の容量 | 調査内容 |
| --- | ---: | --- |
| CMP 100-200 | 約6 GB級 | 12 GB仮説を検証する前に、実バス幅とHBM実装を確認 |
| A30 | 24 GB | 公表仕様は通常構成と整合。ロット別の実装・無効領域を調査 |
| DRIVE A100 / PG199 | 32 GB級（報告値） | 4スタックと密度の確認、32 GB超の正常性は未確認 |
| CMP 100-210 | 16 GB級 | 1df4/1d84の異なる設定系統と実装密度の比較 |
| A30X | 24 GB | 通常の8 GBスタックで説明可能。否定的な実機報告もあり |

CMP 170HXとCMP 100-100は対照例。P100・V100・A100の通常モデルは仕様比較に用いる。市場価格は補助証拠であり、容量解除の根拠ではない。

## 協力者募集

既に対象GPUを持っている方は、PCI Device/Subsystem ID、基板番号・リビジョン、VBIOS、標準ドライバでの容量・クロック、既知のHBM型番をIssueから報告してください。無改造の読み取り専用報告だけで十分です。失敗、追加容量なし、候補の訂正も歓迎します。

新しい比較を始める際は、**Bounded study proposal**テンプレートで対象個体群・基準容量・追加容量のしきい値・動作環境・終了条件を先に決めてください。探索段階の6個体や2所有者の再現を、母集団の成功率と読み替えません。

追加容量の表示だけではPASSにしません。独立アドレスに対する書き込み・読み出し、予約領域と未試験領域の記録、エラー監視、再起動後の再現を重視します。詳細は[検証手順](docs/validation.md)を参照してください。

個体固有のシリアル・UUID・ホスト名・個人情報を削除し、第三者のファームウェアや秘密情報を公開しないでください。本プロジェクトは改造コード、ヒューズ操作、脆弱性の利用手順を提供しません。既存の正常な機器を危険にさらす必要はありません。

## オフライン計算

```sh
python3 tools/screen.py --input data/devices.csv
python3 -m unittest discover -s tests -v
```

Python 3.10以上、標準ライブラリのみ。GPU・管理者権限・ネット接続不要。未知値は欠損として扱い、推定を確定仕様に変換しません。
